# 融资动态界面表格化呈现规划

## Summary

将前端「融资动态」分类的内容呈现从文章卡片流改为**公司维度的融资信息表格**（10 列固定列），并新增离线生成管线：LLM（DeepSeek）从爬取的文章正文/摘要中抽取结构化融资信息 → 按公司去重合并 → 缺失字段经 **Tavily 搜索 + LLM 综合**补全 → 产出 `public/funding-table.json` 供前端渲染。标签筛选（行业/国家）与搜索逻辑保留，改为对表格行生效。

已确认决策（用户选择）：
- 搜索补全方案：**接入 Tavily 搜索 API**（免费额度 1000 次/月，按公司缓存 7 天控量）
- 数据范围：**与前端数据池一致**（快照日报+周报池 + 最新 Manus feed 中的融资类新闻，约最近一周）

## Current State Analysis

1. **前端**：`app/_components/views/FeaturedView.tsx`（精选）与 `AllAIView.tsx`（全部AI动态）均有 6 类分类 Tab；financing（融资动态）当前用 `ArticleCard` 卡片流按日期分组展示，配套 `TagFilterBar`（industry/region 维度筛选）+ `SearchToolbar`（搜索+来源筛选）。
2. **taxonomy.json:101**：financing 类别已有 `"display": "table"` 设计意图，但 grep 确认该字段**无任何消费方**（前端未实现）。
3. **数据现状**：
   - `public/snapshot.json`：daily+weekly sections（前端池，实测 79 条 items，其中 financing 9 条，判定字段 `classification.cat === "financing"`；条目含 title/summary/url/classification，**不含正文**）
   - `data/manus/current.json`：Manus feed（targetDate 2026-08-20，含 summary/classification，不含正文；正文哈希 `contentSha256`）
   - `work/manus/{date}/raw/content-batch-*.json`：文章**全文**（仅保留最近若干天，按 account_name+article_url+title 索引）
4. **LLM 层**：`scripts/llm_common.py` 的 `call_llm(tx, system, user, timeout)`（OpenAI 兼容、JSON mode、自动加载根目录 .env）；缓存/预算/并发模式参考 `scripts/enrich_news.py`（`enrichment_cache.json` + ThreadPoolExecutor + budget）。
5. **无 web search 能力**：DeepSeek API 不支持联网搜索；`.env` 现有 `MANUS_API_KEY`、`DEEPSEEK_API_KEY`；设置页（`SettingsView.tsx` FIELDS 数组）与本地设置服务（`scripts/settings-server.mjs`，SECRET_KEYS 集合）管理密钥并写 .env。
6. **测试**：`python -m pytest tests/ -q` 离线 134 个（MockLLM 注入模式见 `tests/test_enrich_news.py`）+ `node --test tests/rendered-html.test.mjs`。
7. **CI**：仅 `.github/workflows/fetch-manus.yml`（每日 01:00 北京时间，阶段 A 发现→B 正文→C 加工晋升 feed，已注入 DEEPSEEK_API_KEY；提交 feed 回仓库）。update-snapshot.yml 已删，快照由本地跑 `build_snapshot.py` 提交。

## Proposed Changes

### A. 后端：融资表格生成脚本（核心新增）

**新增 `scripts/funding_table.py`** — 融资表格生成 harness（纯标准库 + 复用 llm_common）：

1. **输入装配**：
   - 读 `public/snapshot.json`，取 daily+weekly sections 的 items，按 id 去重（同前端 `poolFromSnapshot` 逻辑），筛 `classification.cat === "financing"`
   - 读 `data/manus/current.json`，筛 financing 条目，按 id 去重后追加（覆盖快照滞后的场景）
   - 正文关联：Manus 条目（`sourceType === "wechat"`）从 `work/manus/{targetDate}/raw/content-batch-*.json` 按 title+article_url 匹配回填 `content_text`；匹配不到或非 Manus 条目用 title+summary
2. **LLM 抽取**（每篇文章 1 次调用，复用 `call_llm`）：
   - system prompt 定义输出：`{"companies": [{company_name, product_name, founded, country, industry, team, business, investors, total_funding, valuation}], "has_funding_info": bool}`
   - 约束：仅陈述文中事实、缺失字段输出 null、禁止臆造；非融资内容（分类误判）返回空数组
   - 结果按「文章 id + 内容 sha」缓存到 `data/funding/extraction_cache.json`（增量运行，模式同 enrichment_cache）
3. **去重合并**（确定性代码，非 LLM）：
   - 公司名归一化：strip、统一全角/大小写、剥离常见后缀（Inc/Ltd/LLC/有限公司/股份有限公司/科技公司 等）
   - 按 publishedAt 降序处理，更新的文章非空字段覆盖旧值；收集 `sourceArticles`（id/title/url/publishedAt/mpName）；`dims`（industry/region 标签）取最新源文章的 classification tags（供前端筛选）
   - 行 id = `"fund:" + 归一化名 md5 前 16 位`
4. **Tavily 搜索补全**（仅对缺失字段 ≥1 的公司）：
   - 每公司 1 次 Tavily search（query = 公司名 + 产品 + "融资 估值"）取 top 5 → 1 次 LLM 调用综合搜索结果填缺失字段
   - 补全的字段名记入 `filledBySearch`；搜索原文 URL 记入 `searchSources`
   - 搜索结果按公司缓存 `data/funding/search_cache.json`（TTL 7 天）
   - 未配置 `TAVILY_API_KEY` 或搜索失败：跳过补全、缺失留空，**脚本不失败**（`searchStatus` 留痕）
5. **输出（原子写，同 build_manus_feed 模式）**：
   - `data/funding/current.json`（权威产物 + `data/funding/archive/{date}.json` 按日归档）
   - `public/funding-table.json`（前端消费）
   - schema：
```json
{
  "schemaVersion": 1,
  "generatedAt": "ISO 时间（北京）",
  "coverageNote": "覆盖快照日报+周报池与最新 Manus feed 中的融资类新闻（约最近一周）",
  "stats": {"articlesProcessed": 0, "articlesWithoutFundingInfo": 0, "companiesTotal": 0, "companiesSearched": 0},
  "companies": [{
    "id": "fund:xxxxxxxxxxxxxxxx",
    "company_name": "自变量机器人",
    "product_name": null, "founded": null, "country": "中国",
    "industry": "具身智能/机器人",
    "team": "...", "business": "...", "investors": "...",
    "total_funding": "...", "valuation": "...",
    "dims": {"industry": "ai_other", "region": "cn"},
    "filledBySearch": ["founded", "valuation"],
    "searchSources": ["https://..."],
    "sourceArticles": [{"id": "manus:...", "title": "...", "url": "https://...", "publishedAt": "...", "mpName": "机器之心"}]
  }]
}
```
6. **CLI**：`python scripts/funding_table.py [--no-promote] [--skip-search] [--selftest]`（selftest 离线自检，模式同 enrich_news）
7. **可测试性**：`build_funding_table(...)` 接受注入的 `llm_fn` / `search_fn`（MockLLM 模式，同 build_manus_feed 的 enrich_fn 注入）

### C. 前端：表格视图

1. **`app/_lib/types.ts`**：新增 `FundingCompany` / `FundingTable` 类型（与上述 schema 对齐）
2. **`app/_lib/api.ts`**：新增 `loadFundingTable(): Promise<FundingTable | null>`（fetch `/funding-table.json`，失败返回 null）
3. **新增 `app/_components/FundingTableView.tsx`**（受控组件）：
   - props：`dimSel`（当前维度筛选）、`q`（搜索词）；内部 fetch 表格数据（模块级缓存，跨切换保留）
   - 渲染 10 列表格（列序固定）：**公司名称、产品名称、公司成立时间、国家、所属行业、团队情况、主营业务、历史投资人、累计融资金额、最新估值**；每行 = 1 家公司/产品
   - 公司名称渲染为链接 → 最新源文章 url（保留 mp.weixin.qq.com 原文链接可达，AGENTS.md 硬性规范 1）；title 提示列出全部来源标题
   - 行筛选：`dims` 匹配 TagFilterBar 语义（行业/国家维度内 OR、维度间 AND）+ `q` 匹配公司/产品/行业/投资人文本；默认按最新 `sourceArticles[0].publishedAt` 倒序
   - 宽表格适配：容器 `overflow-x-auto`、首列 sticky、长文本 truncate + title tooltip；null 字段显示「—」
   - 顶部说明条：生成时间 + 「AI 从 N 篇报道抽取、去重为 M 家公司；缺失字段经联网搜索补全」；`filledBySearch` 字段带视觉标记（如浅色小图标），区分文中事实与搜索补全
   - 空态（无融资条目/无公司）：提示文案；加载态骨架屏
4. **`FeaturedView.tsx` / `AllAIView.tsx`**：当 `cat/tag === "financing"` 且表格数据可用时，用 `<FundingTableView dimSel q />` 替换 DateGroup 卡片流；**表格数据不可用（fetch 失败/文件缺失）时回退原卡片流**（降级路径）。TagFilterBar 与搜索框保留不动；financing 表格模式下隐藏来源筛选下拉（表格行无单一来源属性）；Tab 计数仍按文章数（不改）
5. **`app/_lib/taxonomy.ts`**：`TAXONOMY_CATEGORIES` 增加 `display: "table" | "card"` 字段（对齐 taxonomy.json），视图据此判断渲染分支

## Assumptions & Decisions

1. 表格是**构建时产物**（离线脚本生成），非实时：覆盖 snapshot + 最新 feed；前端实时 aihot 新条目要等下次生成才进表格（融资 Tab 的文章计数仍实时）
2. 「融资动态界面」指精选/全部AI动态两个视图的 financing 分类 Tab；**日报/周报视图（DailyReportView）的融资版块保持现状不改**
3. financing 表格模式下来源筛选（一手信源/资讯/推文/公众号）不适用，UI 隐藏该下拉（其余 Tab 不受影响）
4. 「所属行业」列展示 LLM 抽取的行业自由文本（信息量更大）；筛选用的行业/国家枚举标签取自源文章 classification tags，两套并存
5. 公司去重用确定性归一化规则（不再调用 LLM 二次合并，控制成本、保证可测）
6. 搜索补全每公司 = 1 次搜索 + 1 次 LLM 综合；缓存 7 天；免费额度月 1000 次足够（周新增公司约 10-40 家）
7. LLM 抽取失败的文章跳过并计入 stats；整表生成失败不覆盖上一次 `funding-table.json`（沿用 feed 原子晋升语义）
8. 结构化字段与 AI 叙事边界分明（AGENTS.md 硬性规范 4）：`filledBySearch` 明确标记搜索补全字段
9. DeepSeek 模型配置沿用 taxonomy.json 现有 `model` 块（抽取调用与打标签同模型）；funding 块仅管抽取参数与搜索配置

## Verification Steps

1. `python -m pytest tests/ -q` 全绿（134 + 新增）
2. `python scripts/funding_table.py --selftest` 离线自检通过
3. `npm run build` 无错
4. 本地端到端：配置 `DEEPSEEK_API_KEY`（与可选 `TAVILY_API_KEY`）→ `python scripts/funding_table.py` → 检查 `public/funding-table.json` 公司去重与字段完整性
5. `npm run dev` → http://localhost:3000 → 精选 → 融资动态 Tab：表格呈现、行业/国家筛选生效、搜索词过滤行、公司名跳原文、缺失列显示「—」；全部AI动态视图同样验证
6. 降级验证：移除 `public/funding-table.json` 后刷新 → 融资 Tab 回退卡片流
7. `node --test tests/rendered-html.test.mjs` 回归（如受影响）
