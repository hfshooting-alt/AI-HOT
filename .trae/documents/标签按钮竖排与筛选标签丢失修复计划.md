# 标签按钮文字竖排修复 + 标签筛选结果缺失修复计划

## Summary

两个问题的根因均已通过代码分析 + 本地运行时实测（localhost:3000，vinext dev）定位确认：

1. **标签按钮内部文字竖排**：chevron 图标的默认尺寸类被调用方传入的 className 覆盖，SVG 失去宽高，按钮被挤压到仅容文字+内边距的宽度，中文逐字换行形成竖排（实测"行业"按钮 57×51px、"发布主体"按钮 82×89px）。
2. **发布主体筛选后只剩 \~6 条**（release 类 Tab 显示 26 条，勾选全部 3 个发布主体后仅 5\~6 条）：`mergePools` 用**不带 classification 标签**的实时流条目整体覆盖了同 id 的**带标签**快照条目，导致 LLM 标签被剥离。

## Current State Analysis

### 问题 1：标签按钮文字竖排

* [TagFilterBar.tsx:18](../../app/_components/TagFilterBar.tsx) `ChevronDownIcon({ className = "size-3.5" })` 的默认参数是尺寸类。

* [TagFilterBar.tsx:72](../../app/_components/TagFilterBar.tsx) 调用时传 `className={`transition-transform ${open ? "rotate-180" : ""}`}`，**完全替换**默认值 → SVG 无宽高 → 按钮内容宽度被挤压，`发布主体` 4 个字逐字换行（实测按钮 82px 宽、89px 高 ≈ 4 行）。

* 浏览器实测其他结论：分类 Tab 横向排列正常；按钮之间横向排列正常；问题只在按钮内部文字换行。

* 全仓排查：其余图标调用（BookmarkIcon、SearchIcon、GearIcon、BrandLogo 等）均显式带尺寸类，`ChevronDownIcon` 是唯一被覆盖默认尺寸的调用点；`CheckIcon` 未传 className，不受影响。

### 问题 2：发布主体筛选后只剩 \~6 条

* `/api/featured`、`/api/all` 代理上游 aihot API，返回条目**没有 classification 字段**（实测 live 流 45 条全部无标签；上游字段只有 id/title/category/score 等）。

* LLM 标签只存在于本地快照 `public/snapshot.json`（release 类 29 条中 23 条有标签：创业公司 9 / 大厂/非创业公司 13 / 其他 1）。

* [api.ts:91-101](../../app/_lib/api.ts) `mergePools` 中 `map.set(key, { ...it, id: key })` 用实时条目**整体覆盖**同 id 快照条目 → classification 丢失。

* `categoryOf` 走旧六版块兜底映射，Tab 计数仍显示 26；但运行时 26 条 release 中 21 条无"发布主体"标签（实测分布：无标签 21 / 创业公司 3 / 大厂 2），勾选后仅 5 条匹配——与用户报告的 6 条吻合。

* 精选视图（FeaturedView，经 /api/featured）与全部AI动态视图（AllAIView，经 /api/all）共用 `mergePools`，两个视图均受影响。

## Proposed Changes

### 1. [app/\_components/TagFilterBar.tsx](../../app/_components/TagFilterBar.tsx) — 修复 chevron 尺寸类被覆盖

把默认尺寸类改为固定拼接、调用方 className 追加，而非默认参数替换：

```tsx
function ChevronDownIcon({ className = "" }: { className?: string }) {
  return (
    <svg className={`size-3.5 ${className}`} viewBox="0 0 16 16" fill="none" aria-hidden>
      ...
```

调用处（line 72）不变。修复后"发布主体"按钮预期约 96×33px，文字单行横排。

`CheckIcon` 保持不变（调用未传 className，默认 `size-3.5` 生效）。

### 2. [app/\_lib/api.ts](../../app/_lib/api.ts) — mergePools 覆盖时保留快照 classification

```ts
export function mergePools(snapshotPool: NewsItem[], liveItems: NewsItem[]): NewsItem[] {
  const map = new Map<string, NewsItem>();
  for (const it of snapshotPool) map.set(it.id, it);
  for (const it of liveItems) {
    const key = it.id.startsWith("aihot:") ? it.id : `aihot:${it.id}`;
    const prev = map.get(key);
    map.set(
      key,
      prev
        ? { ...prev, ...it, id: key, classification: it.classification ?? prev.classification }
        : { ...it, id: key },
    );
  }
  // 排序逻辑不变
}
```

语义：实时条目字段（标题/摘要/时间等）仍以实时为准；仅当实时条目缺少 classification（当前上游必然缺失）时回落到快照的 LLM 标签。同时删除原有冗余的 `if (map.has(it.id)) map.set(it.id, { ...it })` 分支（live 条目 id 已带 `aihot:` 前缀，该分支实际是同 key 重复写入）。

### 3. 数据侧说明（不改代码）

实时流中晚于最近一次快照构建的新条目（当前约 3 条 release）确实无标签，需等每日快照构建管线（`build_snapshot.py` + `tag_news.py`）回填标签后才能被筛出。预期修复后：勾选全部 3 个发布主体 ≈ 23/26 条；仅勾"创业公司" ≈ 9 条；仅勾"大厂/非创业公司" ≈ 13 条。这与用户"条目都打上标签、方便筛选浏览"的诉求一致。
