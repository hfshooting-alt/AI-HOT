## 1. 背景与目标

### 1.1 业务背景

融资动态表格按公司维度聚合展示近一周融资新闻（约 10 列：公司名称、产品名称、成立时间、国家、行业、团队、主营业务、投资人、累计融资额、最新估值），由 `funding_table.py` 离线生成。用户核心投资方向为 **AI 泛娱乐（AI 游戏 / AI 社交 / AI 互动内容等）与初创公司**，当前表格无法支撑该聚焦视角。

### 1.2 优化目标

| # | 问题 | 目标 |
| --- | --- | --- |
| 1 | 每行无法跳转原新闻 | 每家公司可访问其全部来源报道 |
| 2 | 行业标签不符合关注方向，且无公司类型区分 | 引入融资专属行业枚举 + 公司类型枚举，可按「AI 泛娱乐 × 初创公司」筛选 |
| 3 | 表格模式下标签筛选失效 | 行标签与筛选枚举对齐，筛选真正过滤表格行 |

## 2. 现状与问题分析

### 2.1 现有数据链路

```
数据池（snapshot.json daily/weekly + data/manus/current.json，筛 financing 条目）
  → LLM 逐篇抽取公司级信息（缓存优先，funding_table.py extract_articles）
  → 按归一化公司名去重合并（merge_companies：新文章字段优先，旧文章补空）
  → Tavily 搜索补全缺失字段（可选，需 TAVILY_API_KEY）
  → schema 校验（validate_table）→ 原子晋升 public/funding-table.json
  → 前端 FundingTableView 渲染（tableMode：分类 display="table" 且产物有公司行，否则回退卡片流）
```

### 2.2 问题定位（含证据）

**问题 1：无原文跳转**
- 仅「公司名称」列是链接，且只跳 `sourceArticles[0]`（最新一篇）；一家公司有多篇来源报道时其余不可达。
- 数据层无缺口：每行已携带完整 `sourceArticles: [{id, title, url, publishedAt, mpName}]`（[types.ts](file:///c:/Users/wade.liu/Downloads/Garena/AI%20HOT2/AI%20HOT/ai%20hot-site/aihot-site/app/_lib/types.ts) `FundingCompany`），**仅缺前端渲染**。

**问题 2：行业不符关注方向**
- 表格列 `industry` 是 LLM 抽取的自由文本（如「具身智能/机器人」），不可枚举筛选。
- 行 `dims.行业` 沿用源文章打标结果：[funding-table.json](file:///c:/Users/wade.liu/Downloads/Garena/AI%20HOT2/AI%20HOT/ai%20hot-site/aihot-site/public/funding-table.json) 实测 6 行 `dims.行业` 全部为「其他AI应用」，无法支撑泛娱乐聚焦。
- 无「初创公司 / 大厂」区分维度。

**问题 3：表格模式下标签筛选失效**
- 功能代码存在：`FundingTableView` 的 `matchRowDims` 按 `rec.dims` 过滤；`TagFilterBar` 在表格模式也正常渲染。
- **失效根因在数据层值域脱节**：行 dims 行业取值（仅「其他AI应用」）与筛选枚举（[taxonomy.ts](file:///c:/Users/wade.liu/Downloads/Garena/AI%20HOT2/AI%20HOT/ai%20hot-site/aihot-site/app/_lib/taxonomy.ts) `TAXONOMY_DIMENSIONS.industry`：游戏引擎 / AI社交/陪伴 / AI游戏内容 / AI互动内容/社区 / AI模型 / 其他AI应用）几乎无交集 → 勾选任何行业要么全表保留、要么全表筛空，表现为「不起作用」。

## 3. 总体设计

### 3.1 设计原则

1. **融资专属枚举，独立于全局分类体系**：行业 / 公司类型枚举定义在 `taxonomy.json → funding` 节点下，供 `funding_table.py` 与前端筛选共用；不触碰全局 `dimensions`，不影响 `tag_news.py` 全站打标（改动面与回归风险最小）。
2. **标签由 LLM 判定，不沿用源文章分类**：依据正文（必要时含搜索补全信息）判定行业与公司类型，比含糊的源文章标签更准确。
3. **默认不过滤**：表格默认展示全部公司，仅提供筛选能力；「默认只看泛娱乐 + 初创」的聚焦视图如需启用，单独确认后追加（见 §10-5）。
4. **失败兜底不中断**：枚举抽取失败回退「其他」，不丢弃公司行；沿用现有「校验失败不晋升」语义。

### 3.2 问题 → 方案 → 改动映射

| 问题 | 方案 | 后端改动 | 前端改动 |
| --- | --- | --- | --- |
| 1 无原文跳转 | 新增「来源」列 | 无（数据已具备） | `FundingTableView` 新增列；公司名列改纯文本 |
| 2 行业/类型不符 | 融资专属行业 + 公司类型枚举，LLM 打标 | `taxonomy.json` 枚举；`funding_table.py` 抽取/合并/校验 | 新增 `fundingTaxonomy.ts`；筛选条切换维度定义 |
| 3 筛选失效 | 行 dims 与筛选枚举对齐 | `merge_companies` 重构行 dims | `TagFilterBar` 支持注入维度定义；两视图切换 |

## 4. 后端改动

### 4.1 taxonomy.json：融资专属枚举

在现有 `funding` 节点下新增两个枚举块（不触碰全局 `dimensions`）：

```json
"funding": {
  "content_input_chars": 16000,
  "timeout_seconds": 90,
  "concurrency": 3,
  "budget_seconds": 600,
  "search": { "...": "保持不变" },
  "industry_dim": {
    "label": "所属行业",
    "values": [
      {"id": "game", "label": "AI游戏"},
      {"id": "social", "label": "AI社交/陪伴"},
      {"id": "interactive", "label": "AI互动内容/娱乐"},
      {"id": "creation_tool", "label": "AI创作工具/生产力"},
      {"id": "model_infra", "label": "AI模型/基础设施"},
      {"id": "embodied", "label": "具身智能/机器人"},
      {"id": "other", "label": "其他"}
    ],
    "fallbackValueId": "other"
  },
  "company_type_dim": {
    "label": "公司类型",
    "values": [
      {"id": "startup", "label": "初创公司"},
      {"id": "big_corp", "label": "大厂/已上市"},
      {"id": "other", "label": "其他"}
    ],
    "fallbackValueId": "other"
  }
}
```

说明：
- 枚举 id/取值以用户最终确认为准（尤其 AI 泛娱乐细分粒度，见 §10-1）。
- 实现侧直接从 `tx["funding"]["industry_dim"]` / `tx["funding"]["company_type_dim"]` 读取；`funding_cfg()` 会把非 `_` 前缀键一并并入 cfg，但无消费方读取这两个键，无副作用。

### 4.2 funding_table.py：抽取阶段

**Prompt 变更**（`build_extract_prompt`）：
- `FUNDING_PROMPT_VERSION` 由 1 → 2（缓存键 `article_cache_key` 含 `fpv` 版本号，自动作废旧抽取缓存，无需手工清理）。
- 输出字段清单新增两个必填枚举字段：
  - `industry_id`：所属行业枚举 id，白名单 = `funding.industry_dim.values[].id`；判定依据为公司产品/业务的泛娱乐细分，模糊时取 `other`。
  - `company_type_id`：公司类型枚举 id，白名单 = `funding.company_type_dim.values[].id`；依据融资轮次（早期轮次 → 初创）、是否上市/头部平台判定。
- 枚举白名单（id + 中文 label 对照）写入 system prompt，LLM 只能从白名单取值。
- 输出格式示例 JSON 同步加入两个字段。

**解析与归一化**（`normalize_company_fields`）：
- 新增独立元组 `ENUM_FIELDS = ("industry_id", "company_type_id")`，不并入 `COMPANY_FIELDS`（后者是展示列，枚举 id 仅作 dims 来源）。
- 枚举 id 校验：取值在白名单内 → 保留；缺失 / 非法 → 回退对应 `fallbackValueId`（`other`）。**不因枚举非法丢弃整条记录**（`company_name` 仍是唯一必填项），保证公司行不丢。

### 4.3 funding_table.py：合并阶段（merge_companies）

行 `dims` **不再沿用源文章 dims**（旧「行业」键值全为「其他AI应用」，正是问题 2/3 根源），改为全新构建三个键：

```json
"dims": {
  "所属行业": "<industry_id → funding.industry_dim label>",
  "公司类型": "<company_type_id → funding.company_type_dim label>",
  "国家/地区": "<region label>"
}
```

- `所属行业` / `公司类型`：取该行各来源文章抽取记录中**最新非空**的枚举 id 转 label（与字段级合并策略一致：publishedAt 降序处理，新文章优先、旧文章补空）。
- `国家/地区`：优先沿用源文章 dims 的 region label（全局 region 枚举）；缺失时用 LLM 抽取的 `country` 自由文本做确定性映射（如「中国」→「中国」、「美国/US」→「美国」、「新加坡」→「东南亚」），映射表实现于 `funding_table.py`，无命中回退「其他」。
- 维度键命名说明：融资行业维度 label 为「所属行业」，与全局行业维度 label「行业」不同名，`DimSelection` 键语义天然隔离；且两视图切换分类 Tab 时本就清空 `dimSel`，无串扰风险。

### 4.4 funding_table.py：校验阶段（validate_table）——关键细节

`validate_table` 现以 `tx["dimensions"]` 构建 `dim_labels` 合法集（[funding_table.py](file:///c:/Users/wade.liu/Downloads/Garena/AI%20HOT2/AI%20HOT/ai%20hot-site/aihot-site/scripts/funding_table.py) L553-554）。**新维度「所属行业」「公司类型」不在全局 dimensions 中，若不扩展合法集，所有行校验都会失败，整表拒绝晋升**。必须：

- 将 `funding.industry_dim` / `funding.company_type_dim` 的 label→values 集合并入 `dim_labels`（全局 dimensions 与融资专属 dims 取并集）。
- 校验语义保持不变：行 dims 每个 `label=value` 必须落在合法集内，违规抛 `ValueError` → 不覆盖上一次产物。

### 4.5 行业自由文本列（industry 列）保持不变

表格「所属行业」列仍展示 LLM 抽取的自由文本（如「具身智能/机器人」），提供比枚举更细的业务描述；枚举标签仅用于筛选。两者同名但职责不同（列 = 描述，维度 = 筛选），属可接受的设计取舍。

## 5. 前端改动

### 5.1 新增 app/_lib/fundingTaxonomy.ts

导出融资表格专属维度定义，键为维度 id、结构与 `TAXONOMY_DIMENSIONS` 一致（`{label, values: string[]}`），取值与 `taxonomy.json → funding.*_dim` 枚举 label 及全局 region label 对齐：

```ts
export const FUNDING_DIMENSIONS: Record<string, { label: string; values: string[] }> = {
  industry:     { label: "所属行业", values: ["AI游戏", "AI社交/陪伴", "AI互动内容/娱乐", "AI创作工具/生产力", "AI模型/基础设施", "具身智能/机器人", "其他"] },
  company_type: { label: "公司类型", values: ["初创公司", "大厂/已上市", "其他"] },
  region:       { label: "国家/地区", values: ["中国", "美国", "欧洲", "东南亚", "日韩", "其他"] },
};
export const FUNDING_DIM_IDS = ["industry", "company_type", "region"] as const;
```

### 5.2 TagFilterBar.tsx：支持注入维度定义

- 新增可选 prop `dimsDef?: Record<string, { label: string; values: string[] }}>`，缺省回退全局 `TAXONOMY_DIMENSIONS`——其余 Tab 行为零变化。
- 组件内 `TAXONOMY_DIMENSIONS[dimId]` 的两处查表（`DimDropdown` 与 `TagFilterBar` 主体）改查 `dimsDef ?? TAXONOMY_DIMENSIONS`。
- `dims` prop 语义不变（维度 id 列表）；融资表格模式下传 `FUNDING_DIM_IDS`。

### 5.3 FeaturedView / AllAIView：表格模式切换维度来源

两个视图改动一致（各约 3 行）：
- `activeDims` 计算：`tableMode` 时返回 `FUNDING_DIM_IDS`，否则沿用 `TAXONOMY_CATEGORIES` 的类别 dims。
- `TagFilterBar` 调用处：`tableMode` 时追加 `dimsDef={FUNDING_DIMENSIONS}`。
- 依赖注意：`activeDims` 的 `useMemo` 依赖数组需加入 `tableMode`（其由 `fundingTable` 异步加载后从 false → true 翻转）。

### 5.4 FundingTableView.tsx：来源列 + 搜索增强

**新增「来源」列**（`COLUMNS` 追加，`sourceArticles` 本就是 `FundingCompany` 的键）：
- 位置：「最新估值」之后，作为最后一列（`w-[200px]`）。
- 单元格：渲染 `rec.sourceArticles`，每条一行外链（`target="_blank" rel="noopener noreferrer"`），显示 `mpName + 截断标题`（完整标题放 `title` 提示）；来源数量典型为 1–3 条，全量展示不折叠。
- 「公司名称」列改为纯文本（跳转职责移交「来源」列，避免同一跳转重复出现两处）；说明条文案同步把「点击公司名跳最新报道原文」改为「点击「来源」列标题跳原文」。

**搜索增强**（`matchRowQuery`）：匹配字段在现有公司/产品/行业/投资人基础上，增加「公司类型」标签值与 `sourceArticles[].title`。

**筛选逻辑**（`matchRowDims`）无需改动：其按键（维度中文 label）读取 `rec.dims`，行 dims 已含三个新键，维度内 OR、维度间 AND 语义自然生效。

## 6. 数据结构变更

`funding-table.json` 顶层与公司行字段结构不变（`schemaVersion` 保持 1）；仅行内 `dims` 的键集合变化：

| dims 键 | 取值来源 | 取值域 |
| --- | --- | --- |
| `所属行业` | `industry_id` 枚举映射 | `funding.industry_dim` 枚举 label |
| `公司类型` | `company_type_id` 枚举映射 | `funding.company_type_dim` 枚举 label |
| `国家/地区` | 源文章 region 标签，缺失时 country 文本映射 | 全局 `region` 枚举 label |

旧产物的「行业」键不再产出（dims 全新构建）。`sourceArticles` / `filledBySearch` / `searchSources` 结构不变，前端「来源」列直接消费。`types.ts` 无需改动（`dims` 本为自由键值对）。

## 9. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 枚举白名单过严导致 LLM 大量回退「其他」 | 白名单含 `other` 兜底；上线后抽查回退比例，必要时调整枚举粒度（仅改 prompt + 版本号 +1，缓存自动失效） |
| `validate_table` 合法集扩展遗漏导致整表晋升失败 | §7.1 校验用例覆盖；`--no-promote` 模式可先试跑不落盘 |
| 前端 `dimsDef` 注入影响其他 Tab | prop 可选且缺省回退全局定义；§8-5 回归验证其他 Tab |
| 旧缓存导致新字段缺失 | `FUNDING_PROMPT_VERSION` +1 已使抽取缓存键失效，无需手工清理 |

回滚方式：改动均为增量（新枚举块 / 新列 / 可选 prop），git revert 对应提交即可恢复；`funding-table.json` 产物由下次旧版本脚本运行自然覆盖。

## 附录：术语表

| 术语 | 含义 |
| --- | --- |
| 全局分类体系 | `taxonomy.json → dimensions/categories` + `tag_news.py` 打标链路，服务全站新闻卡片流 |
| 融资专属枚举 | `taxonomy.json → funding.industry_dim / company_type_dim`，仅服务融资表格抽取与筛选 |
| 维度（dim） | 筛选粒度，`{label, values, fallbackValueId}`；筛选条按 label 勾选、行按 `dims[label]` 匹配 |
| 行 dims | 公司行的筛选标签集合（`{维度label: 取值label}`），本次起为三个固定键 |
| 晋升（promote） | 临时文件 + `os.replace` 原子替换产物（`data/funding/current.json` + `public/funding-table.json`） |
| tableMode | 前端融资表格模式：分类 `display="table"` 且构建产物有公司行，否则回退卡片流 |
| FUNDING_PROMPT_VERSION | 抽取 prompt 版本号，参与缓存键；字段/约束变更时 +1 以自动作废旧缓存 |
